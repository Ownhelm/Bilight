# Bilight for iPhone

独立运行的原生 SwiftUI 客户端，最低 iOS 17。手机直接连接 B 站，不依赖 Mac、Docker 或 Bilight 网页后端。首页只有居中的搜索框，底部进入关注动态，不提供推荐、热搜或自动连播。

原生界面可通过[离线演示](../docs/demo.md)查看；宣发截图和公开内容图片不随源码仓库分发。

## 构建与安装

用支持 iOS 17 及以上的 Xcode 打开 `Bilight.xcodeproj`。选择 **Bilight → Signing & Capabilities**，开启自动签名，选择自己的 Apple Team，再把 Bundle Identifier 改成自己的唯一标识。仓库没有预置个人 Team 或签名资料。

选择已连接的 iPhone，点击 Run。首次运行需要按 iPhone 提示启用开发者模式，并在“设置 → 通用 → VPN 与设备管理”中信任对应开发者；Apple ID 和安全验证由本人在 Xcode 完成。个人账号签名的有效期以 Xcode 提示为准，过期后重新构建安装即可。

启动后在 App 内打开官方登录页并完成登录。App 只读取自己临时登录页面中的会话，存入设备 Keychain，不读取 Safari 或其他应用中的 Cookie，不会上传给 Bilight 服务端。

当前版本通过 Xcode 从仓库源码构建。发布页保留历史交付，其中 `Bilight-iOS-unsigned.ipa` 没有 Apple 签名和设备描述文件，不能直接安装；没有 App Store／TestFlight 下载渠道。

## 日常使用

首页搜索框居中，上方展示 Bilight 标识和“搜你所想，看你所选”，顶部导航栏保持简洁；首页和搜索结果页使用一致的胶囊形搜索框。搜索支持视频、UP 主、视频链接与 BV 号。UP 主页面区分投稿、合集和列表，选中分组后才加载其中内容；关注按钮使用无底色的细描边和小尺寸线性图标，点击即可切换，取消关注不弹二次确认。

关注页按时间展示已关注账号的视频、文字、图文、转发和专栏摘要；逐页核验关注关系，过滤平台插入内容。靠近页尾继续加载，也保留手动加载，最新内容统一下拉刷新，标题旁不放刷新按钮。搜索、合集、评论与历史手动分页。

已读取的关注动态、分页与浏览位置在当前账号会话内保留。从视频或 UP 主页返回、切换搜索与关注时直接恢复，只有主动下拉刷新才重新获取最新内容；刷新失败仍保留原卡片。退出账号会清空缓存，取消关注只移除对应作者的动态。

原生播放器首次默认最高实际可用 AVC 画质，之后恢复上次选择；无对应档位时选取较低的可用画质，后续支持原档位时自动恢复。DASH 音视频通过本机分段适配器边读取边交付，只监听 iPhone 的回环地址；完整分段按 Range 缓存，单播放源最多64MiB，停止时清理。全屏切换复用同一播放器和缓冲，不重复重设播放状态。横屏直接进入全屏，画质、倍速与字幕设置共用状态，字幕可用时默认开启且优先中文，评论默认展开。点开视频或手动切换分 P 后自动播放，播放结束停止；暂停后切换画质仍保持暂停。

全屏缩放按钮在约1.5秒无操作后自动淡出，轻点画面重新显示或隐藏，避免持续遮挡视频；点击退出直接回到内嵌播放，竖屏全屏时也可在视频画面向下滑动退出；竖屏及刚打开全屏时均可退出，保留进度、倍速与播放状态。

播放页依次展示播放器、UP主信息、标题与播放信息，再呈现三连操作；操作栏下用浅灰线分隔分P、简介和评论。标题、UP主信息和操作栏按可用宽度适配不同iPhone尺寸，支持系统大字体；空间不足时操作栏自动换行，保留至少44pt触控区。视频操作栏以手机端的小图标及紧凑间距呈现点赞、投币、收藏，三项靠左成组，真实数量放在下方，下载位于最右侧；弹幕和字幕统一收进播放器齿轮设置。轻点点赞切换状态，持续长按点赞蓄力完成一键三连，中途松开或移开取消；投币可选剩余数量及同时点赞，收藏可选择、取消或新建收藏夹。投币不可撤回，互动失败不会自动重试，结果不确定时须先刷新状态。

双击视频左侧后退10秒，双击右侧前进10秒，内嵌、全屏和离线播放均可用；画质、倍速、字幕和弹幕统一在播放器内设置。字幕可选语言或关闭，弹幕只保留开关、字号和不透明度。弹幕首次默认关闭，之后恢复上次开关；开关与画质保存在本 App，跨视频、分 P 和重启生效。开启后读取当前分P的真实弹幕，只读且限制显示密度。下载保存在 App 内，完成后可以离线播放或通过系统分享菜单导出；权限、容量和网络错误会如实显示。

底部导航只有“搜索”“关注”，顶部头像打开“我的账号”，下载与历史也可从顶部图标进入。账号页依次为“我的关注的人”“我的收藏”“我的下载”和“常访问的 UP 主”，后者同时展示头像列表；没有单独的“我的最近访问”入口。

“常访问的 UP 主”排序来自 B 站接口，不是本地逐次主页访问记录。视频历史统一读取 B 站云端，实际播放推进后同步真实分 P 和进度；仅打开视频或拖动暂停视频不会生成观看记录。

## 开发与验证

Xcode 工程已经提交，可以直接打开。修改 `project.yml` 后可使用 [XcodeGen](https://github.com/yonaskolb/XcodeGen) 重新生成工程：

```bash
xcodegen generate --spec ios/project.yml
BILIGHT_DESTINATION='platform=iOS Simulator,name=你的模拟器名称' bash ios/scripts/verify.sh test
```

以上命令在仓库根目录执行。`test` 使用内存会话和假上游，不碰真实账号；`live` 是单独的匿名只读播放与下载烟测，会访问网络。`build` 构建模拟器，`archive` 生成未签名 Release archive：

```bash
bash ios/scripts/verify.sh archive
python3 ios/scripts/package-source.py
```

构建缓存默认位于仓库外的 `../Local/Builds/`，源码包与归档位于仓库内被 Git 忽略的 `releases/`。不要提交个人签名证书、描述文件、Keychain 导出或真实观看诊断。

## 离线界面预览

Debug 构建支持启动参数 `--demo`。普通工程仅包含内存会话和 JSON 快照；有外部宣发图片时，运行 `bash ios/scripts/preview.sh` 生成仓库外的可选预览工程，再添加该启动参数。全部 API 请求由本地 URLProtocol 拦截，未覆盖的操作直接报错，写入被禁止，不会回退访问真实 B 站。

详细的截图复现步骤见 [演示说明](../docs/demo.md)。正常启动不带该参数，Release 构建不包含演示执行逻辑。

## 代码布局

`Core/` 处理接口、WBI、会话、云端历史与数据模型；`Features/` 为 SwiftUI 页面；`Playback/` 负责 AVPlayer、DASH 分段、字幕和全屏；`Downloads/` 处理下载、合并、离线观看与导出；`Demo/` 是独立发布预览数据；`BilightTests/` 为隔离测试。

支持的链接包括 `bilight://following`、`bilight://video/BV号`、`bilight://account` 以及账号子路径 `/following`、`/frequent`、`/favorites`、`/downloads`。
